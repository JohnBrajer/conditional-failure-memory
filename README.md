# Conditional Failure Memory

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23718095.svg)](https://doi.org/10.5281/zenodo.23718095) [![ORCID](https://img.shields.io/badge/ORCID-0009--0004--0113--1341-A6CE39?logo=orcid&logoColor=white)](https://orcid.org/0009-0004-0113-1341)


**John Brajer — Possibility Reserve mechanism**

## Principle

A failed attempt is evidence about a possibility **under a particular state and set of conditions**.

It should not automatically become a permanent property of the possibility itself.

Instead of:

```
possibility -> failed -> dead
```

store:

```
possibility + state + conditions + attempt -> outcome
```

## Why

Conditions change.

Resources, timing, tools, collaborators, information, constraints, skill, environment, and goals can all move. A failure recorded without its causal context can cause a system to suppress a possibility long after the reason for failure has disappeared.

## Memory object

A useful failure record includes:

- possibility identifier
- state at attempt
- relevant constraints
- action taken
- observed outcome
- suspected or verified failure causes
- confidence in those causes
- conditions that would justify reconsideration

## Rule

Remember **why and when** something failed, not merely that it failed.
